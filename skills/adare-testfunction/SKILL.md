# ADARE test-functions

A **test-function** is a decorated Python function ADARE calls after a playbook runs
to assert a forensic outcome — "does this file exist", "does this JSON key match this
value", "is this deleted file actually gone". Test-functions live in **collections**
(`testfunctions/<collection>/<collection>.py`) and are referenced from a playbook's
`tests:` block by `<collection>.<function>`.

**Find before you write**: the bundled catalog (about 70 functions) covers most
assertions. Writing a new one is the authoring loop: **scaffold → author (per the
contract) → validate → dry-run → install → integrate**. Pure `adare` CLI + Bash + file editing —
no VM needed until end-to-end integration. Auto-loads as a skill in **Claude Code**;
portable to any agent with a shell (on **OpenCode** see `docsrc/mcp-clients.md`). The
authoring contract and the validate/dry-run detail live in `references/`.

## 0. Find an existing test-function (do this first)

```sh
adare test search "the deleted file is gone"          # ranked, synonym-aware, with a tests: example
adare test search "registry value" --os windows       # filters: --collection, --os, --category
adare test info standard.file_does_not_exist          # signature, types, defaults, parameter docs
adare test info standard.file_does_not_exist --example  # just the tests: block to paste
adare test search "icon visible" --json              # machine-readable
```

No project or VM needed; this reads the collection sources directly. The full
reference is `references/catalog.md` (generated by `adare test catalog --markdown`).
Rules:
- Use the exact dotnotation and parameter names from `test info`. Never guess. An
  unknown name errors with close matches.
- A parameter with a default of `''` is required in practice (e.g. `dst`).
- Prefer the explicit inverse over negating: `standard.file_does_not_exist`, not
  `file_exists` expected to fail.
- Absence of content (a key, value, string, line, text chunk): use the count function
  with `expected_count: 0` (`json.value_count`, `ini.value_count`, `text.occurrence_count`,
  `csv.row_count`, `sqlite.row_count`, `xml.element_count`, ...), or `expect_to_fail: true` on the presence
  test. Both are negative tests (INCONCLUSIVE without proof of the act). A missing or
  unreadable file stays ERROR either way, never a pass.
- Compressed files: `dst: /path/store.jsonlz4!` (LZ4, also gz/bz2/xz and Snappy `.sz`)
  gives the decompressed content to any file test; `a.zip!/member` or
  `a.tar.gz!/etc/app.json` reads an archive member (`.docx`/`.xlsx`/`.odt` are zips).
- Times stored as numbers (Unix seconds or ms, FILETIME, microseconds since 1601, seconds
  since 2001): `expected_value: !timestamp {after: ..., before: ..., epoch: 1601, unit: us}`
  (`epoch` 1970/1601/2001, `unit` s/ms/us/ns/100ns; needs `tolerance` or `after`/`before`).
- Placeholders: an invalid `!re` or an unknown placeholder is an ERROR. `text.*` and
  `standard.file_content_contains` refuse `!re` in `content` (use `text.line_count` with
  `regex_match`, or `standard.file_content_matches_regex`).
- Renamed (old names are rejected with "X was renamed to Y"): `csv.line_count` →
  `csv.row_count`; `expected_text`/`expected_result`/`expected_element` → `expected_value`
  (`xml.element_text_matches`, `xml.xpath_result_matches`, `json.array_contains`);
  `text.occurrence_count` `encodings` → `encoding`; `jsonl.line_matches` `match_mode` →
  `wildcard_mode`; `excel.sheet_exists` `sheet_name` → `sheet`; `sqlite.query_result`
  `expected_rows` → `expected_count`; `linux.log_entry_exists` `log_file`/`pattern` →
  `dst`/`content` (+ `regex_match`, default true).
- Formats: json, jsonl, csv, xml, excel, sqlite, ini, plist, yaml, toml, image (PNG text
  chunks, EXIF, dimensions), text (raw byte/encoding search, line counts), standard.
- `visual.*` tests run on the host against the VM screen (text/image/icon). Use them
  for UI state, not for files.

### Choosing between look-alikes

Same table as `docsrc/source/guide/choosing-testfunctions.rst`, short form.

| Goal | Use | Not this one |
|---|---|---|
| file created / deleted | `standard.file_exists` / `standard.file_does_not_exist` | `expect_to_fail` on `file_exists` |
| how many files match a glob; none left | `standard.file_count` (`expected_count: 0`) | `file_exists` (passes on any match) |
| file is empty / non-empty / grew | `standard.file_size` (`expected_size: 0`, `greater`) | `file_content_equals` with empty content |
| string written into a text file | `standard.file_content_contains` | `text.occurrence_count` unless counting |
| string occurs n times, or wiped, in any file (binary, cache, UTF-16) | `text.occurrence_count` (`encoding: [utf-8, utf-16-le]`) | `file_content_contains` (one encoding, no count) |
| lines of a text file containing a string/regex | `text.line_count` | `text.occurrence_count` (counts occurrences) |
| trace in the last lines of a plain-text log | `linux.log_entry_exists` | `text.line_count` when counting/whole file |
| CSV records matching a layout | `csv.row_count` (`csv.contains_line` for one) | `text.line_count` (quoted line breaks) |
| JSONL records meeting conditions | `jsonl.line_count` / `jsonl.line_matches` | `jsonl.value_in_any_line` (one field only) |
| value of a setting (json/ini/plist/yaml/toml) | `<format>.value_matches` | `<format>.contains_key` (ignores the value) |
| how many values; key/value absent | `<format>.value_count` (`expected_count: 0`) | `value_matches` + `expect_to_fail` |
| SQL rows / row count or gone | `sqlite.query_result` / `sqlite.row_count` | `text.occurrence_count` on the `.db` (misses WAL) |
| spreadsheet cell / row / count / sheet | `excel.cell_value_matches` / `contains_row` / `row_count` / `sheet_exists` | |
| XML text, office metadata (`.docx` author) | `xml.element_text_matches` (`report.docx!/docProps/core.xml`, `./dc:creator`) | `xml.xpath_result_matches` (typed results) |
| photo EXIF / PNG text chunk / stripped | `image.exif_value_matches` / `image.png_text_matches` / `*_count` with 0 | |
| on screen | `visual.exists` / `visual.not_exists` / `visual.count_*` | file tests |

Only if nothing fits, write a new collection (sections 1–7).

## 1. Scaffold

```sh
adare test create <name>                 # new collection under testfunctions/<name>/
```

`test` aliases: `tf`, `testfunction`. Creates the collection skeleton — a directory
whose `.py` filename **must equal** the directory name (a contract rule).

## 2. Author

Edit `testfunctions/<name>/<name>.py`. Each test is a plain function decorated with
`@testfunction(...)`:

```python
from adarelib.testset.api import testfunction, TestContext
from adarelib.testset.basictest import HostModeCategory
from adarelib.event.event import TestResult

@testfunction(
    name='file_exists',
    description='tests if file(s) exist',
    category=HostModeCategory.FILE_BASED,
)
def file_exists(ctx, dst: str, match_mode: str = "any"):
    paths, status = ctx.resolve_globfilepath(dst, match_mode=match_mode, return_list=True)
    ctx.error_if(status, f'path {dst} cannot be resolved ({status})')
    files = [p for p in paths if Path(p).is_file()]
    ctx.fail_if(not files, f'no files match {dst}')
    return [f'{len(files)} file(s) found']
```

**Non-negotiable contract rules** (enforced at load time — see
`references/authoring-contract.md` for the full list and the `category` types):

- First parameter **must** be `ctx` (a `TestContext`).
- **Every** other parameter must have a type annotation (drives cattrs validation of
  the playbook's `parameter:` block). Give defaults where sensible.
- `name=` must be **unique within the collection**; the file must be named after its
  directory.
- Assert with `ctx.fail_if(cond, msg)` (test failed) / `ctx.error_if(cond, msg)`
  (precondition/setup error); return a str/list (success) or a `TestResult`.
- **Failed means the evidence was read and the condition does not hold.** A missing
  `dst`, a glob matching no file or several, unparseable content or invalid parameters is an *error*, never
  a failure: `expect_to_fail` inverts only success/failed, so a failure there would let a
  wrong path pass a negative test. Only existence tests (`file_exists`,
  `file_does_not_exist`) may fail on a missing path.
- **A test whose pass means "something is absent"** (cleared, deleted, never written)
  should declare `@testfunction(..., negative=True)` (a count function needs no flag:
  `expected_count: 0` is recognised as negative). The host then reports an
  unproven pass (an earlier GUI action skipped or without visible effect) as
  INCONCLUSIVE instead of SUCCESS, so every playbook that uses it gets that for
  free. Names ending in `_does_not_exist` are recognised without the flag. Tell
  playbook authors to pair it with a control test (`controls:`), see the
  adare-playbook skill. A missing file/key must be reported by the test itself, not
  inferred from a read error: only a real "not found" may pass.

## 3. Validate (offline, no VM)

```sh
adare test validate <path>               # collection dir or .py file
```

Static contract check: filename≠dirname, missing `ctx`, unannotated params,
duplicate testnames, import/syntax errors, missing dependencies — each with a fix
hint. **Never install a collection that doesn't validate.**

## 4. Dry-run (against a local sample, no VM)

```sh
adare test dry-run <collection>.<function> -P key=value -f <sample-file>
```

Executes **one** `FILE_BASED`/`FILE_CONTENT` test against a local sample used as the
`dst` parameter — the fast way to prove the logic without booting a VM. `-P` is
repeatable for the function's other parameters. Details in
`references/validate-dryrun.md`.

## 5. Install

```sh
adare test load <name> [--force]         # register a collection (name/path)
adare test sync                          # sync all appdata testfunctions (new/changed/unchanged)
```

`test load` skips testfunctions currently used in experiment runs by default;
`--force` overwrites them **and deletes the associated runs** — use deliberately.

## 6. Inspect

```sh
adare test list [--collection standard] [--os windows]   # every testfunction + parameters
adare test info <collection>.<function>                  # detail for one testfunction
adare test versions <collection>[.<function>]            # version history
adare test remove <name>                                 # remove a collection file
```

## 7. Integrate

Reference the installed test from a playbook's `tests:` block as
`<collection>.<function>` with a `parameter:` block matching the function's annotated
signature, then run it at the right moment with a `- test: <name>` action:

```yaml
tests:
  - name: report_deleted
    description: 'The report must be gone after the delete action'
    function: standard.file_does_not_exist
    parameter:
      dst: '{{ report_file }}'
actions:
  # … GUI actions that delete the file …
  - test: report_deleted
```

Write a docstring with an `Args:` section for every new function. The catalog, `test
info` and the agent tools show it, and `test validate` warns when it's missing. Docstring
edits don't bump the function's version. Wiring the `tests:` block into the playbook itself is `adare-playbook`;
verify the whole thing end-to-end with a real `adare exp run` (`adare-experiment`) —
the dry-run only proves the function in isolation.

## Guardrails

- **Validate before install.** `test validate` is offline and fast; a collection
  that fails it will fail at load/run.
- **`test load --force` deletes runs** tied to the testfunction — confirm first.
- **Contract is enforced at load time**, not run time — a missing annotation or a
  bad `ctx` signature raises loudly on load. Fix at authoring, don't work around.
- **No VM needed** for scaffold/author/validate/dry-run; only end-to-end integration
  (`exp run`) touches a VM (and is serialized — one live VM at a time).
- **Forensic integrity:** test-functions read guest-pulled artifacts on the host;
  keep them side-effect-free (no writes into the guest, no remnants).
